## 二、网络配置（**这部分最容易踩坑，务必看**）

### 现象

本机在校园网内，浏览器会自动使用校园代理 `proxy-dku.oit.duke.edu:3128`，但：

| 目标 | 直连 | 走校园代理 |
|---|---|---|
| `mirrors.tuna.tsinghua.edu.cn`（清华镜像） | ✅ 快 | ❌ **403 Forbidden** |
| `pypi.org`（官方 PyPI） | ❌ 不通 | ❌ 不通 |
| `github.com` | ❌ 超时 | ✅ 通 |

### 关键陷阱

**Python 的 requests / conda / pip 会自动读取 macOS 系统代理设置**（而 curl 不会）。
结果是：`conda install` 默认走校园代理 → 访问清华镜像 → 403 → 报
`ProxyError: Conda cannot proceed due to an error in your proxy configuration`。

### 解决方案（已配置好）

1. **pip 永久指向清华镜像** —— 写入 `~/.config/pip/pip.conf`
2. **conda 永久指向清华镜像** —— 写入 `~/.condarc`
3. **镜像域名绕过代理** —— 写入 `~/.zshrc`：

```bash
export no_proxy="mirrors.tuna.tsinghua.edu.cn,mirrors.ustc.edu.cn,mirrors.aliyun.com,localhost,127.0.0.1"
export NO_PROXY="$no_proxy"
```

### 如果以后又遇到下载失败

```bash
# 装 Python 包时临时彻底绕过代理（最保险）
unset http_proxy https_proxy
export no_proxy="*"
pip install 包名

# 需要从 GitHub 拉取时，反过来显式挂代理
export https_proxy=http://proxy-dku.oit.duke.edu:3128
```

> **一句话记住**：**镜像直连、GitHub 挂代理**。

## 二·补：OpenMP 冲突（**最隐蔽的一个坑，务必知道**）

### 现象

装完所有包后，`import torch` 直接崩溃：

```
OMP: Error #15: Initializing libomp.dylib, but found libomp.dylib already initialized.
OMP: Hint This means that multiple copies of the OpenMP runtime have been linked
into the program. That is dangerous, since it can degrade performance or cause
incorrect results.
Abort trap: 6
```

### 原因

环境里同时存在**两份 OpenMP 运行时**：

| 来源 | 位置 |
|---|---|
| conda-forge 的 `llvm-openmp`（被 scikit-learn 等依赖） | `~/miniconda3/envs/medimg/lib/libomp.dylib` |
| **pip 版 PyTorch 自己捆绑的那份** | `.../site-packages/torch/lib/libomp.dylib` |

两个库同时被加载 → 运行时冲突 → 进程直接 abort。

### 排查方法

```bash
# 找出所有 OpenMP 副本
find ~/miniconda3/envs/medimg -name "libomp.dylib" -o -name "libiomp5.dylib"

# 逐个包测试导入，定位是谁触发
for m in numpy SimpleITK radiomics torch sklearn cv2 napari; do
  printf "%-12s " "$m"; python -c "import $m" 2>&1 | tail -1
done
```

### 解决方案（本机采用）

**改用 conda-forge 版 PyTorch**，让所有包共用同一份 OpenMP：

```bash
pip uninstall -y torch torchvision
conda install -n medimg -c conda-forge pytorch torchvision
```

修复后：`import torch` 正常，14 个包可同时导入，**MPS（Apple GPU）加速可用**。

> ⚠️ **备选方案（不推荐作为首选）**：设 `KMP_DUPLICATE_LIB_OK=TRUE` 能让程序跑起来，
> 但官方明确说这"可能导致崩溃或静默产生错误结果"。科研代码要的是可信，不是能跑。

### 教训

**在 conda 环境里混用 pip 安装的深度学习框架，是 macOS 上最常见的崩溃来源。**
以后遇到"某个包单独导入正常、一起导入就崩"，第一反应就是查重复的底层运行库。

## 三、日常使用

### 启动环境

```bash
conda activate medimg          # 激活
conda deactivate               # 退出
```

激活后命令行提示符前面会出现 `(medimg)`。

### 常用命令

```bash
python script.py                    # 运行脚本
jupyter lab                         # 启动交互式 notebook（浏览器自动打开）
conda list                          # 查看已装包
pip install 包名                     # 装新包（自动走清华镜像）
conda install -c conda-forge 包名    # 用 conda 装
```

### 检查环境是否正常

```bash
python -c "import numpy, SimpleITK, radiomics, torch; print('环境正常')"
```

## 四、还差一项：3D Slicer（图形界面阅片工具）

**3D Slicer 是临床科研的标准阅片/勾画软件**，目前尚未安装（它的下载接口较特殊，自动安装未成功）。

**请手动安装（约 5 分钟）**：

1. 浏览器打开 👉 **https://download.slicer.org/**
2. 选择：
   - Operating system: **macOS**
   - 版本：选 **Stable Release**（稳定版，不要选 Nightly）
   - 架构：**Apple Silicon**（你的机器是 arm64）
3. 下载 `.dmg` 文件
4. 双击打开，把左边的 **Slicer** 图标拖到右边的 **Applications** 文件夹
5. 首次打开若提示"无法验证开发者"，去 `系统设置 → 隐私与安全性` 点"仍要打开"

**装好之后的第一件事**：打开 Slicer → `File → Add Sample Data`，加载示例数据，用 `Segment Editor` 试着勾画一个区域 —— 这就是你未来所有分割任务的起点。

### 临时替代方案

在装好 Slicer 之前，可以用 **napari**（已装好，Python 原生 3D 查看器）：

```bash
conda activate medimg
napari
```

## 六、给未来的自己：三条经验

1. **版本不是越新越好** —— 科研生态滞后，选一个"被广泛支持的版本"（如 Python 3.11）比追新重要得多。
2. **网络问题不等于操作错误** —— 今天卡住最久的不是命令写错，而是"代理 + 镜像"的组合问题。遇到下载失败，先怀疑网络路径。
3. **每装一个新包，跑一次最小验证** —— 不要只看 `pip install` 成功，要 `import` 一下，最好跑一个真实的小任务。
